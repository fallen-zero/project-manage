# M5.5 设计 —— 监听只标脏 + 写侧减锁 + 清账批（13 项单批）

依据 `docs/技术方案.md`、M5 规格 `docs/superpowers/specs/2026-10-10-m5-reconcile-design.md`（尤其 §九 那张 M5.5 欠账表）、M5 整分支终审报告 `.superpowers/sdd/2026-10-10-m5-reconcile/branch-review-m5.md`（Recommendations 第 2/3/4 条是本批头三项的出处）。执行方式仍是 `superpowers:subagent-driven-development`。

- **范围声明（先说死）**：需求方 2026-10-12 裁定 **13 项合并成一批做完**，不拆「本体 / 历史债务清账」两批。这反转了本仓「里程碑账超十项先拆两批」的默认规矩，代价（批次越大计划本体被返工的面越大，M4 那个 9 任务的计划本体改过 16 次是前科）已在派发前点名并被接受。**本 spec 不擅自缩量**：§九 那节仍然给每条写上归属，但它是「万一撑不住时的第二优先队列」，不是预设的砍单清单。
- **行号纪律**：本文所有 `文件:行号` 都是 2026-10-12 在 `master`（M5 已合入，`c00cc72`）的当下读数，**只作对照，取数只认命令**（本仓同形错已记七次，`docs/HANDOFF.md` 坑 65/67/73/86/92 与 §5 L 组）。落点一律用符号定位，例：`grep -n "pub fn write_doc" src-tauri/src/index_store.rs`。
- **两条历史红线在本批破例**（必须显式记账，不许当成「顺手加个依赖」）：① **首次新增依赖**（`notify`），破的是从 M3 守到 M5 的「零新依赖」；② **首次引入常驻后台句柄**（watcher 线程 + ticker），M5 只有「跑完即止」的一次性作业线程，本仓**没有**常驻句柄的生命周期先例。两条都进第九节风险。
- **本批守住的**：零新 IPC 命令（`generate_handler!` 仍 **41**）、零新线格式字段（`SearchBundle` 七键 / `DocPreview` 六键两条断言照旧绿）、零新迁移（`TARGET_VERSION` 仍 **4**）、`Cargo.toml` 的 `features` 不动（依赖那一行只为 notify 破例）。

## 一、本轮交付与边界

五组，其中只有第 ① 组是新机制，其余是减害与清账：

| 组 | 内容 | 新机制？ |
|---|---|---|
| ① | **监听只标脏**：`notify` watcher 收事件 → 置一个 `AtomicBool` → ticker 见脏且空闲时起一次**整库追平轮** | 是（依赖 + 常驻句柄） |
| ② | **写侧减锁 + 只改文案**：`write_doc` 的分词外提出事务；`busy` 那类错单独给一句人话 | 否 |
| ③ | **`setup` 抽 `bootstrap(data_dir)`**：让启动触发那一格「有断言可红」 | 否（纯内部重构） |
| ④ | **M4/M5 未收的账面清账 7 条**（见第四节末表，逐条写闭法或「预期不红」） | 否 |
| ⑤ | **`missing` 体积实测**：只量不删，删除入口不做 | 否 |

**边界（明确不做）**：见第九节。最要紧的三条是 watcher **不做热重注册**、**不给 `missing` 做批量删除入口**、**不做「关掉自动追平」的开关**（技术方案 §九 那句「设置页可关」这一半本轮仍不兑现，需求方 2026-10-12 逐条确认）。

## 二、决策与理由

| 编号 | 决策 | 被否掉的备选与理由 |
|---|---|---|
| D1 | 监听粒度 = **只标脏，追平仍走那一整轮**（需求方选定） | ① 事件直接改写单行（秒级、最省 IO）：要新开一条**不经闸门**的写入通路，而 M5 那三道闸门（root 不可达 / 截断 / 比例熔断）之所以成立，正因为所有回收都走「整轮比对」；单点通路把它们全绕过 ⇒ 风险面大于收益。② 不上 `notify`、改常驻轻定时器（每 2 分钟一轮）：零依赖零常驻句柄，但里程碑名里那一半就是监听，且它给的是「固定周期」而不是「变了才跑」，空闲时白扫 |
| D2 | 脏标记的形状 = **一个 `AtomicBool`，不是项目集合** | 派发前我先写成 `Mutex<HashSet<projectId>>`，核接口后翻掉：`index_job::start`（`index_job.rs:434`）的第四参是 `project_id: Option<String>`（**单个**项目），`targets()`（`:96`）同样只吃 `Option<&str>` ⇒ 现有接口喂不了「脏项目集合」，而追平轮本来就该扫全部（`None`）。所以脏标记唯一够用的语义是「**有没有东西变过**」这一布尔；上集合等于为用不上的粒度设计（本仓 `ponytail` 视角当场判过度设计）。**不扩 `start` 的签名**——那要连带动 `run_pass`、前端 `index_start` 的实参与 41 条 handler 的形状，买不到任何本批需要的东西 |
| D3 | 起轮的触发器 = **ticker 轮询布尔**，不在 watcher 回调里直接起轮 | 回调里直接 `start`：一次 `git checkout` / 解压缩会瞬间来几千条事件 ⇒ 要么在回调里自己攒去抖窗口（等于把 ticker 换个更难测的地方写），要么高频撞 `running` 单飞、白刷 `index_running` 错误。ticker 天然是去抖器（5 s 一轮询，一个窗口内几百次变更只起一轮）。回调里只做 `store(true)`，**绝不碰 SQLite**（回调跑在 notify 内部线程，直接写库等于绕过 `running` 闸门，见第五节落点 1） |
| D4 | ticker = **`std::thread` + `sleep` 自己起一个**，不引 tokio interval 进 UI 侧，也不引第三方定时器 | 本仓 `index_job` 已经是「自己开连接、自己起线程」的形状（`index_job.rs` worker 自持连接），ticker 同形最省、可测面也最干净；`tauri` 侧的异步运行时只被 `doc_preview` 那条 async 命令用到，往里塞常驻 interval 会把「谁持有它、怎么停」变成运行时问题，而本轮要的恰恰是能被读出来的简单生命周期 |
| D5 | 写侧口径 = **减锁时长 + 只改文案**，不改成「快速失败」也不让自动轮让路（需求方选定） | ① 快速失败 + 「稍后再试」提示：界面确实不冻了，但 `project_update` 是**编辑项目档案的保存**，失败即「用户输入要自己搬回来」，重做成本在需求方那侧；本工具的写命令是低频小额，5 s 冻一次远好过丢一次输入。② 自动轮在首个写命令到达时让路：要新增「轮 ↔ 命令」会商机制，M3 定稿的 `index_job`/`db` 形状质变，量级和 D1②同批都不小。③ 只做文案不做减锁：留着那几个 4.2 s 的**直接来源**不处理，等于把最便宜的一格让给最贵的一格去解决 |
| D6 | 减锁的具体动作 = **把 `write_doc` 事务内求值的两个 `index_text()` 提到 `unchecked_transaction()` 之前**（终审独立复核为真，控制方再到 `index_store.rs:46/:85/:88` 逐行确认） | 不是新想法，是终审给出的「唯一不需要产品决策就能做的减害」：`:46` 开事务、`:49` 第一句 INSERT 已取到 SQLite 写锁，而 `:85` 的 `params![rowid, index_text(&file.file_name), index_text(&body)]` 里那两个调用 = `cut_for_search` + 逐词 `String` 分配 + `join` ⇒ 锁持有时间 ≈ 分词一个大正文 + 两条 INSERT。抽取本身确在锁外（`run_pass` 里那句 `match panic_to_err(|| extract_text(..))` 先把正文抽出来，落库在该 match 的 `Ok(body)` arm 里调 `write_doc`），所以**只有分词在锁内**这一处是白烧的。备选「把 `busy_timeout` 从 5 s 调大/调小」被否：调大更冻、调小更容易把保存打成失败，两者都不如少持锁 |
| D7 | 文案落点 = **在 `error.rs:42` 的 `From<rusqlite::Error>` 里单拉 `DatabaseBusy` 一支**，其余 rusqlite 错一律不动 | 现状是所有 rusqlite 错无差别映射成 `db_failed` + 原文（终审已核：`error.rs:42-49`），所以「只改文案」有且只有这一个落点。**不新增错误码**：`hint` 字段本来就在回线上（`ipc.ts` 的 `AppErrorShape` 带 `hint`，M5 的 D10 已让预览那句红字把它拼上屏），复用 `hint` 零线格式改动；新开一个 `db_busy` 码要改 M4 §七 的码表契约，那属于「先改契约再实现」，不在本批范围 |
| D8 | `setup` 那一格 = **只抽 `bootstrap(handle, data_dir, index, preview)`，不开 `tauri` 的 `test` feature、不动 `Cargo.toml` features**（需求方选定） | 终审（Important-2）证伪了 M5 登记的「本环境 `tauri::test` 不可用」：`tauri-2.12.0/src/lib.rs:1129-1131` 是 `#[cfg(any(test, feature = "test"))] pub mod test;`、`Cargo.toml:123` 的 `test = []` 只是空标记 feature、`src/test/mod.rs:166` 的 `mock_builder()` 返回 `Builder<MockRuntime>` 不建真实窗口且 `.build()` 会跑 setup 钩子。真实阻碍只有两条：开 feature（本批不想动 `Cargo.toml` 的 features，依赖那一行只为 notify 破例，不想破第二条）、以及 `mock_context` 的 `identifier = Default::default()`（空串，`test/mod.rs:116`）+ `app_directories_override: None`（`:125`）会让 `app.path().app_data_dir()` 解析到**真实用户目录**、`db::open` 在那儿落 `ledger.db` ⇒ **撞只读红线**。用 `tempdir` 直测 `bootstrap` 就把这两条一起避开；代价照实记：测的是 `bootstrap` 而非 setup 那一行的真实接线，那一行仍由真机断言兜（与 M3 缺口 2 同口径） |
| D9 | `missing` 行 = **本轮只补体积实测，不做删除入口**（需求方选定） | 终审建议原话：「清理入口就是 `clear_project` 的形状，别再造第三个写入口」——`missing` 的单一**生产**写入点是 M5 刚被整分支终审判为 HELD 的不变量（B 条），加批量删等于给它开第二个写通路。先用几千行 `missing` 的实测字节数决定「该不该在意」：若可忽略，删除入口 YAGNI；若涨得明显，再连清理入口 + 体积策略一起做（那时它是新功能，不是清账） |
| D10 | 真机规模这一格 = **拿需求方的一个真实项目量一次**（而非再灌沙盒） | M3/M4/M5 三轮的结论都是「沙盒数字不代表真实目录」，而自动轮现在是每次启动都跑、本批又加了「变了就跑」——触发频率只增不减，却没在真实规模上取过一次数。沙盒灌到 5 万行仍是合成语料（文件均匀、正文便宜），回答不了「真实项目一轮多久、峰值多少」。代价：这一格需要人配合、不可全自动，写进第七节点名 |

## 三、状态口径与契约（本轮一律不扩词汇表）

| `index_status` | 写入方 | 本轮变化 |
|---|---|---|
| `pending` | 无生产写入点（CHECK 默认值） | 不动 |
| `ok` | `write_doc` | 只在「分词求值时刻」这一内部细节上变（D6），落库形状一字不动 |
| `skipped` | `write_doc`（`too_large`/`empty_text`/`type_unsupported`） | 不动 |
| `failed` | `write_doc` 的 `Failed` arm | 不动 |
| `missing` | `mark_missing`（唯一**生产**写入点；例外：`db.rs` 的 CHECK 枚举用例用裸 INSERT 写过一次，那是库层用例不是产品通路） | 不动，也不给删除入口 |

**契约层的三条「不动」**（本批全部改动都发生在这些约束之内，是裁定的落点，不是随手选择）：

1. **零新 IPC 命令**：监听、ticker、bootstrap 全在 Rust 内部。`generate_handler!` 的条数门必须仍读 41（正则要**逗号可选**，`^ +[a-z_]+,?$`；要求尾逗号那版恒读 40 —— 本仓连踩两次，坑 94/96）。
2. **零新线格式字段**：`search.rs:774` 的七键断言、`doc_preview.rs:371` 的六键断言照旧绿，且**不许靠删断言达成**（M5 终审用 `git diff --stat` 证明过这件事的字面形态，本批要同样给）。
3. **零新迁移**：`TARGET_VERSION` 仍 4（`db.rs:85`），`dirty` 只是内存态，不落库、不进 `settings` 表。

**新增的内部契约（不是线格式，但同样是跨模块不变量，评审要盯）**：

- `dirty: Arc<AtomicBool>` 是「自上次追平之后有过文件事件」的**唯一**位点；置位方只有 watcher 回调，复位方只有 ticker（且必须在 `start` **之前**，见第四节）。
- watcher 线程**永不调用任何写库函数**。它唯一的副作用是 `store(true)`。理由：回调运行在 notify 内部线程，若直接写库就绕过 `index_job::start` 开头 `running.swap(true, SeqCst)`（`index_job.rs:441`）那个单飞闸门，会出现两条连接同时改 `index_docs`。
- `bootstrap` 是 setup 体的**唯一**入口，`setup` 只负责取 `data_dir` 再调它；`db::open` 仍只在这一条链上被调用（真机与测试的区别只在传进来的 `data_dir`）。

## 四、判据（本轮的规格核心）

### ① 监听这一链的正确判据

- **置脏**：任何落在「已登记且当前可达的 root」子树下的事件 ⇒ `dirty=true`。事件种类不区分（创建/删除/改名/metadata 都只置同一个布尔）；区分它们属于 D1②那条被否的路。
- **消费**：ticker 每 5 s 看一次，**两个条件同时成立才起轮**：`dirty == true` **且** `index.running == false`。
- **顺序是判据不是风格**：**先 `swap(false)` 清脏，再 `start`**。反了会怎样要能讲出来：轮跑期间（分钟级）进来的新事件会把脏位又置上，而轮结束时 ticker 立刻又起一轮 ⇒ 一轮接一轮白跑，且第二轮的集合与第一轮高度重叠。可自愈（不会错标），但那是把 CPU 花在重复扫上。**落法**：`let was_dirty = dirty.swap(false, SeqCst); if was_dirty { start(...) }`，一条原子操作把「读+清」并起来，避免先 `load` 后 `store` 丢掉中间的事件。
- **root 变更 / 新登记项目不重注册 watcher**（第九节明写为不做）⇒ 新项目的变更在「下一次启动轮」或「其它已注册 root 的事件顺带触发的那一轮」里被追平（追平轮是 `targets(None)` 整库，所以只要有任何一次起轮，新项目的行也会被建）。这条要在文档里说准成「新项目的事件不单独触发轮，但会被下一次因别的原因起的轮覆盖到」，**不许写成「监听覆盖所有项目」**——那是假话，且是这一格最容易长出来的假话。
- **watcher 注册失败不阻断启动**：某个 root 不可达（移动盘没插是本工具的常态用法，M5 已把它列为一等场景）或 `watcher.watch()` 返回 Err ⇒ 记进 `last_error` 还是静默？**静默跳过，不写 `last_error`**。理由：`last_error` 的既有语义是「一轮索引失败的原因串」，界面上那一段标题是「上一轮索引未正常完成」（M5 终审 Minor-8 刚改准），把「没监听成」写进去会让用户以为索引出了错。监听注册失败的实际后果只是「少一些自动触发」，方向与 D1 的保守性一致，且启动轮照跑。这一格记为**有名取舍**，界面不可见。

### ② 写侧的两条判据

- **减锁要能被证伪**。首选形态是**行为断言**：在同一进程里用两条连接，一条**只持写锁不做分词**（例如开事务、执行一条 UPDATE、sleep 住不 commit），另一条调 `write_doc`；断在「锁已被占」的情况下，分词阶段**不产生 busy**、只有进入 INSERT 才 busy。能被打红的方向是：把那两个 `index_text()` 挪回 `params![]` 里 ⇒ 求值时刻回到锁内 ⇒ 该断言红。**若本机造不出这个并发时序**（`db::open` 的第二连接、WAL 活着时的行为见 `docs/HANDOFF.md` 环境结论），退化为文本门禁 `grep -c "index_text(" src-tauri/src/index_store.rs` 配合「`index_text` 必须出现在 `unchecked_transaction` 之前」的行序检查（同文件既有先例：`include_str!` + 数 `.cut(` 恰 1 次，坑 10）。**两个形态都要在计划里写明，并显式记哪一个有守护、哪一个只是当下能红**。
- **文案只动 `busy` 那一支**。判据：断 `From<rusqlite::Error>` 对 `SqliteFailure{code: DatabaseBusy, ..}` 回的是新 `message` 前缀 + 非空 `hint`；对其它 rusqlite 错（用 `SQLite::Error::SqliteFailure` 造一个非 busy 的）**仍回原文与 `db_failed`**。变异「把 busy 分支删掉」必须让第一条红；变异「让所有错都走新文案」必须让第二条红。

### ③ bootstrap 的判据

- 抽完之后，`bootstrap(app_handle, tempdir_path, index, preview)` 必须能**在无窗口的测试里跑通**：断 `ledger.db` 落在喂进去的 tempdir、`journal_mode=wal` 读回成立、起轮失败（把 data_dir 指向一个不可写的路径）时 `IndexShared::last_error` 有值。
- 一条**边界断言（本格的形状约束，不是可选项）**：`bootstrap` **不起 watcher、不起 ticker**，那两个常驻线程由 setup 在 `bootstrap` **返回之后**起。理由：`bootstrap(tempdir)` 要在单测里被反复调用，若它内部起常驻线程，测试会留下僵尸 watcher（风险 2 正是这件事）⇒ 「起不起常驻」必须是 setup 与 bootstrap 的切分线。落法：`grep -n "watch::start\|spawn" src-tauri/src/lib.rs` 的命中要落在 setup 段而非 bootstrap 段（具体行号计划阶段现取）。
- 一条**红线守护断言**：`bootstrap` 绝不接收「来自 `app.path()` 的默认目录」这条路径作为参数默认值——测试里传什么就用什么。落法：签名只有 `data_dir: PathBuf` 必填参数、无 `Default`，且 `grep -n "app_data_dir" src-tauri/src/lib.rs` 的命中数从（本轮现取）减到 1，且那一行必须落在 setup 里而不是 bootstrap 里。**否则红线二（真实用户目录）只是被换了个位置踩。**

### ④ 清账 7 条的逐条闭法（每条都要给「能不能被打红」的实话）

|---|---|---|---|

### ⑤ 体积实测的判据

- 沙盒：同一批文件跑两轮，第一轮全 `ok`，第二轮删掉一批文件造出几千行 `missing`。**造法有讲究**：熔断的条件是「缺少数过半 **且** 缺少数 > 20 行地板」（`index_job.rs` 的 `candidates*2 > tracked.len() && candidates > MISSING_FUSE_MIN_ROWS`），所以要让标记**真的执行**，每个项目只缺 **≤ 半数**（例如各缺 40%），靠**项目数**把总量堆到几千行；反之若一次把一个项目删到只剩两成，会被熔断挡下、一格都不标，测不到体积。这条与 M5 真机断言 6 是同一判据的两面（那轮验的是「挡住了」，本轮验的是「放行时攒多少行」） ⇒ 断 `missing` 行数落在预期、只回 `ledger.db` 与 `-wal` 的**字节数**与「同规模全 ok 基线」的差。
- **只回数字，不打印任何正文**（红线 5）。结论二选一写进开发进度：「可忽略 ⇒ 删除入口 YAGNI，本格关掉」或「显著 ⇒ 记为 M6 的新功能（清理入口 + 体积策略一起设计）」。

## 六、错误处理

- **watcher 建不起来 / 单 root 注册失败**：跳过该 root、继续注册其余、**不写 `last_error`**（理由见第四节①末条）、不阻断启动、不 panic。这一格的可观测性为零，显式记为有名缺口（界面看不出「这个 root 其实没被监听」），靠启动轮兜底。
- **ticker 起轮失败**：写 `last_error`，与 M5 的 `index_spawn_failed` 那条链复用到底（M5 已把「起轮失败不许静默」落成真事，本批不重做也不削弱）。
- **写命令 `busy`**：5 s 后回新文案 + `hint`，**不重试、不改数据**（保存失败由用户重试，见 D5）。
- **监听事件风暴**：由 D3 的 ticker 天然吸收（一个 5 s 窗口内几百条事件 ⇒ 一次 `store(true)` ⇒ 最多一轮）。
- **`stitch` 病态载荷**：本批要么随第 ④-2 格把 `hits`/窗口口径定死，要么照 M5 现状继续挂着；**不许**出现「加了超时但没加复位通路」的半个闸门。

## 八、真机验收（含需要需求方配合的格）

一次性 identifier `dev.zero.pfm.m55test`，跑完连沙盒目录与孤儿进程（vite 1520 / `msedgewebview2.exe` 9222）一起删净；真实数据目录 `%APPDATA%\dev.zero.pfm\` 前后按 size+mtime+SHA-256 三行逐字对照；`-c` 覆盖走 `npm run tauri -- dev -c '{...}'` 且动手前先做那两个必然失败的编译前探针；子代理一律不跑 `tauri dev`，真机由控制方亲自执行；探针每步单独一次 `evaluate`、只回布尔/条数/错误码名，**绝不打印抽出的正文**；给 sync 命令计时必须在空队列上取（坑 81）；**写侧与读侧都要量**（坑 100）。

断言（计划阶段逐条落为可照抄粒度）：

1. **监听兑现（本批主承诺）**：改一个已索引文件（追加一段可检索的新串）⇒ **不重启、不点按钮** ⇒ 等 ticker（≤5 s + 一轮时长）后该行的正文命中出现/更新；删一个文件 ⇒ 同样无人工动作 ⇒ 该行转 `missing` 且正文不再命中。这条把 M5 那句「重启才能看见」真正翻成「看得见」。
2. **不撞轮**：手动点「建立索引」的同时制造事件风暴（一次改 200 个文件），断终态**只有一轮**在跑、没有连环轮（`index://progress` 终态计数 + `running` 曲线）；并量一轮期间的读侧与**写侧**耗时（写侧必须重跑，M5 的教训是只量读侧会得到 2–10 ms 的漂亮数字）。
3. **新项目那一格说实话**：新建项目并登记 root **之后**再往那个目录写文件 ⇒ 断「不会因这个新项目的事件起轮」，但下一次因别的 root 事件起的轮会把它的行建出来。**这条是断言不是缺口**——它验的就是第四节①末条那句边界。
4. **`bootstrap` 真机侧**：`db_status` 读回的 `journal_mode/schema_version/fts5_available` 三项 + 沙盒目录落在 `dev.zero.pfm.m55test`（不是真实 identifier）。
5. **写侧新文案**：在自动轮进行中做真实编辑保存，若越线则界面念到新那句（含 `hint`）；量到几次越线照实记。
6. **`missing` 体积**：几千行 `missing` 常驻时 `index_docs` 清单与项目卡计数仍能对上、库文件字节数（数字进第五组结论）。
7. **真实项目量一次（需求方配合）**：耗时 / 峰值内存 / 追平延迟三个数 + 一句观感，不打印正文。
8. **清场**：沙盒与 `%TEMP%` 夹具删净、真实目录逐字未变、1520/9222 无监听、`tauri.conf.json` 一字未动。

**没能自动验证（逐条点名，不许省略；写进开发进度的 M5.5 节）**：watcher 真实文件事件的时序（本机只验接线）；某个 root 注册失败在界面上不可见（第六节那条有名取舍的直接后果）；网络盘/SMB 事件风暴与跨卷行为（本机无网络设备可造）；watcher 线程与 `tauri dev` 热重载之间的回收行为（多次重启是否有僵尸线程，只能观测到进程退出）；`stitch` 在真实语料上是否可达（要第 ④-2 格的载荷测量给数字）；几十 GB 全量的表现（第 7 条只量**一个**真实项目，不是全量）；JSX 渲染正确性（`node --test` 不覆盖）；簇序第三级 `id` 键（预期不红）。

## 十、风险

1. **首次引入依赖**：`notify` 的行为（去抖、事件合并、跨卷、Windows 上的 `ReadDirectoryChangesW` 语义）本仓零先例 ⇒ 一切关于「它会发几条事件」的假设都只能真机验，单测验不了。缓解：监听**唯一**副作用是置一个布尔，最坏是「多跑/少跑一轮」，不会直接写坏数据。
2. **首次引入常驻线程句柄**：生命周期未定（谁持有、退出怎么收）。M5 只有跑完即止的作业线程。**热重载（`tauri dev` 重启）会不会留僵尸 watcher** 是本批最容易出的真事，只能观测不能断言 ⇒ 写进「没能自动验证」。
3. **触发频率再一次上升**：M5 把索引从「用户点」变成「每次启动都跑」，本批再加「文件一变就跑」。几十 GB 语料下这条可能变成主要成本 —— 而它正是第八节第 7 条要量的东西。**若实测一轮很久，需要回头给 ticker 加最小间隔或按项目收窄触发**（本批先取数再定，不预设阈值）。
4. **减锁断言可能退化成文本门禁**（弱守护）。届时必须在开发进度里写清「这一格由 grep 门守着、不是行为断言」，不许用「有测试」含糊过去（坑 69/89 同族：散文把不存在的守护说成存在）。
5. **`stitch` 与闸门同格是本轮最容易做歪的一格**：只加超时不给复位通路 = 半个闸门；只给 `hits` 设上限会改 `truncated`/`ranges` 语义（M4 已定过「加长度上限会在断开处重演相接窗」那个失效形态，别在这里重犯）。
