## 一、需求确认结论

| # | 结论 | 对架构的影响 |
|---|---|---|
| 1 | 痛点是「上次那个文件/网址/账号在哪」 | 软件是**检索优先**，不是台账优先 |
| 2 | 首屏 = 一个搜索框 | 搜索是默认路由与主导航入口 |
| 3 | 以「项目」为建模中心 | 所有实体挂在 project 下 |

| 8 | 备份选 A：手动导出/导入备份包 | 索引不进备份包，换机器重建 |
| 9 | 先单人，预留多人 | 无服务端；数据模型留稳定 ID、`updated_at`、软删除 |
| 10 | MVP 选 B：搜索 + 项目档案 + 目录映射 + 信息台账 + 加密 | 待办、日报、Excel 全部后置 |
| 11 | 架构：纯桌面；**alova 保留依赖但 v1 不接任何数据源** | 前后端通信用 Tauri IPC |
| 12 | 环境无限制，可装外部工具；以 AI 长期维护为第一目标 | 依赖数量与构建步骤最小化优先 |

### 红线（不可逆操作，永远不做）

- 不移动、不修改、不复制、不重命名任何原始项目文件；只登记路径。
- 不做 Git / 代码查看 / 代码提交。
- 不做数据库连接、SQL 执行、数据库运维。
- 不做云端同步。

## 二、技术选型与依据

### 2.1 检索引擎：SQLite FTS5 自研索引（方案一，已采纳）

被否掉的两条：

- **tantivy + SQLite 双存储**：几十 GB 量级付不起「文件改名/删除要两边同步、备份要打包两处」的一致性代价。搜索质量上限最高，但不是当前瓶颈。
- **嵌 `dowse` 当引擎**：它是纯文件维度引擎，没有台账概念，「搜一个词同时命中项目/网址/PDF 正文并按项目分组」要在应用层拼两次查询再归并，首屏体验割裂；且 crates.io 只到 0.10.0（2026-07-21），GitHub 已 1.1.0 且 OCR 在其后，走 crates.io 拿不到 OCR，走 git 依赖等于钉在单人维护、版本流动的仓库上。
- **复用 Windows Search API：不建议。** 强依赖目标机开启索引服务且范围正确，公司电脑常被 IT 策略关闭；结果无法按项目/标签过滤；换机器行为不一致。

**选 FTS5 的真正理由不是性能，是一处真值来源**：台账、正文索引、索引状态全在同一个 SQLite 文件里，备份、迁移、一致性、按项目/标签过滤全部退化成一个 SQL。

### 2.2 已核实的库内部行为（不是凭印象）

| 论断 | 证据 |
|---|---|
| `rusqlite` 的 `bundled` 一定带 FTS5 | `libsqlite3-sys/build.rs:163` 在 bundled 编译路径上无条件 `.flag("-DSQLITE_ENABLE_FTS5")`，无 feature 开关 |
| `pdf-extract` / zip+XML 解析对畸形输入会 **panic 而非返回 Err** | 借鉴对象 `dowse::extract` 把所有抽取包在 `catch_unwind` 里，注释明确指出这一点 → 抽取必须跑在独立 worker 线程。处置：本项目 `[profile.release]` **不许**设 `panic = "abort"`——abort 下 panic 不展开，`catch_unwind` 在 `tauri build` 产出的包里一个都抓不到，防线只剩 dev 里有（终审 C1）；由 `extract::release_profile_does_not_abort_so_panic_guards_work` 这条构建配置测试钉住 |
| Windows 原生 OCR 会在中文字符间插入空格，不清洗就永远搜不到 | `dowse::ocr::clean_cjk_spaces()` 专为删这个问题而写（仅当空格两侧都是 CJK 才删，保留英文词间空格） |
| 旧格式 .doc 纯 Rust 无可靠方案 | `dowse` 与 `calamine` 都只覆盖 docx/xlsx/pptx/xls，Word 二进制 .doc 不在列 → 需外部 `soffice --headless`。**M7 已在本机（LibreOffice 26.8.1.1）逐条实测**：可执行文件要取 `soffice.com`（同一活儿 `.exe` 慢 5 倍，且 `.exe --version` 零输出）；`--outdir` 只认空格分隔（等号形直接被拒并回吐整页 usage）；`-env:UserInstallation` 必须是全正斜杠 `file:///` URL 且**路径里的空格要写成 `%20`**（用户名带空格那类机器在修复前每一份都零产物快失败）；**退出码不可信**——垃圾字节冒充 `.doc` 也 exit 0 并产出正文非空的 docx，唯一判据是「产物存在 + 抽得出内容」；两份同名源进同一 outdir 会互相覆盖 ⇒ 每笔转换一个一次性目录 |
| LibreOffice 的 profile 不可共用（M7 实测） | 两个实例共用同一个 `UserInstallation` 时抢输的一方 `exit 1` 且零产物（四格对照：同 profile 并行 1 胜 1 败、异 profile 并行两胜、同 profile 串行两胜）⇒ 转换侧的并发靠「每笔独立 out + 独立 profile」消解，**不引入任何进程内锁/信号量/队列** |
| 「不记忆化探测」换来的能力（M7） | LibreOffice 探测只是三次 `is_file()`，成本可忽略 ⇒ 每轮现探一次。与 M6 的 `OnceLock` 有意不同：用户点「安装 LibreOffice」装完后**不必重启应用**，下一轮填 `ScanOptions` 时就探得到、旧格式开始建行 |
| `opener` 的 `allow-open-path` 权限**只放行命令，不含任何路径 scope** | `tauri-plugin-opener-2.7.0/permissions/autogenerated/commands/open_path.toml` 注明 "without any pre-configured scope"；`src/scope.rs:127-140` 把 capability 里该权限的 `allow` 条目喂给 `tauri::fs::Scope`，条目为空即 `is_path_allowed=false` → 只在 permissions 里写字符串会得到 "Not allowed to open path"（M1 真机复现）。本项目必须写成 `{ "identifier": "opener:allow-open-path", "allow": [{ "path": "**" }] }` |
| `navigator.clipboard.writeText` 在 webview 失焦时抛 `Document is not focused` | M1 真机复现（CDP 驱动时窗口未聚焦）。"一键复制路径/密码"是核心动作，静默失败不可接受 → 改用 `tauri-plugin-clipboard-manager` 的原生剪贴板 |

### 2.3 借鉴来源

`ltspace/dowse`（MIT OR Apache-2.0，最近推送 2026-09-28）。**只读源码作参照实现，不作为依赖。** 要借鉴的具体设计：扩展名分派抽取、`chardetng`+`encoding_rs` 编码探测、大小上限与跳过原因、畸形输入的 `catch_unwind`、Windows OCR 队列/worker 池、`reconcile` 启动对账、快慢车道降级思路。

## 三、架构

```
React (WebView)  ── TanStack Router(hash) + zustand + shadcn/ui
      │  只做展示与交互，不碰文件系统
      ▼  invoke() / Tauri IPC（唯一数据通道）
Rust 侧  src-tauri
  ├─ commands   参数校验、返回 DTO
  ├─ service    业务逻辑、事务边界
  ├─ search     jieba 分词 → FTS5 查询 → 结果分组
  ├─ index      walkdir 扫描 → 抽取 → 写库（rayon 线程池 + catch_unwind）
  ├─ extract    按扩展名分派：pdf / docx / xlsx / pptx / text
  ├─ crypto     Argon2id KDF + AES-256-GCM 列级加解密
  ├─ vault      主密钥双包裹、恢复码
  └─ backup     SQLite Backup API 快照 → 剥两张索引表 → zip 备份包（manifest + db，逐条目 SHA-256）
                导入：四道前置全过才动库 → 先在数据目录存应急包 → restore 灌进**已打开的那条连接**
                     ▼
              本地单文件 SQLite（WAL）+ 附件目录
```

**硬性约束：文本抽取、分词、写库、加密全部在 Rust 侧。** 放 webview 会同时丢掉编码控制、流式读取和性能。

### 3.1 数据库打开（不可省校验）

`PRAGMA journal_mode=WAL` 之后**必须读回 `PRAGMA journal_mode` 断言等于 `wal`**，不能相信 `pragma_update` 返回的 Ok——数据目录可能落在网络盘/被杀软拦截的路径，设置会静默失败。校验不过就明确报错并提示换本地磁盘，不静默降级。

### 3.2 中文分词

FTS5 原生 tokenizer 在中文上一定失效且症状隐蔽（`unicode61` 把整句连续中文切成一个巨型 token；`trigram` 要求查询 ≥3 字符，而中文高频是 2 字词）。

做法：**入库前用 `jieba-rs` 切词，以空格连接写入 FTS 列，FTS5 表本身配 `unicode61` 即可**（切词工作已前移）。

**硬约束：入库与查询必须用同一个分词器、同一套预处理**（同版本词典、同停用词、同 lower / 全半角处理）。为此把预处理收敛成一个函数 `tokenize_for_index(s) -> String`，入库和查询两侧共用，禁止任何一侧私自加处理。FTS 虚表用 `rowid` 对齐主表主键，不把业务 id 塞进虚表列。

### 3.3 摘要与高亮策略

不在 token 空间做偏移映射（分词后位置对不回原文）。改为：

- **结果列表摘要**：FTS5 `snippet()` 在 token 文本上生成，展示前做去人为空格清洗。
- **点开命中**：按需从磁盘原文件重新抽取，在**原文**上做子串大小写不敏感高亮。既省存储又准确，且符合「只读、不动源文件」的边界。

### 3.4 跨域结果合并

台账（SQL 匹配）与正文（FTS BM25）的分数不可直接比较。**不做假的归一化**：结果按「项目 / 台账条目 / 文件正文」分组展示，组内各自按 BM25 或时间排序，命中的台账与文件在所属项目下聚合。

## 四、数据模型

```
projects            项目：名称/编号/经理/客户/对接人/合同编号/合同周期/交付截止/status/标签/parent_id（自引用，M13）
                    status 为全局统一枚举：立项|需求|开发|测试|预发|上线|运维|归档
                    parent_id 自引用 projects.id（单父树，M13 V9；只建 idx_projects_parent_id，无外键/不级联）
project_audit_logs  项目信息修改日志（M14 新增，V10）：id / project_id（快照关联，无外键）/ project_name（项目名快照）/
                    action（create|update|delete）/ changes（JSON 字段级旧值/新值）/ created_at；只追加、永久保留、无软删。
workspaces          工作区（M15 新增，V11）：id（TEXT PK）/ name（UNIQUE）/ created_at；`default`（默认工作区）由 V11 种，不可删。
projects.workspace_id（M15 新增，V11，NOT NULL DEFAULT 'default'）：逻辑分区归属；存量行由 ADD COLUMN 语义自动回填，迁移零 UPDATE。
settings.active_workspace_id（M15 新增）：当前活动区，后端记住；读不到兜回 `default`（兜底不是主路径）。
project_tags        自定义标签（政务/自研/外包/已验收/暂停/维保中/…）
project_dirs        目录映射：kind = root(一个) | entry(多个快捷入口)，仅存路径
ledger_envs         多环境：env = dev|test|pre|prod，名称/URL/端口/备注
ledger_credentials  账号凭据：绑定 env 或独立，username_*_cipher / password_*_cipher（各配 *_nonce）
ledger_servers      服务器 IP / 堡垒机 / 远程账号：account_*_cipher / password_*_cipher（各配 *_nonce）
ledger_links        外部链接：Jira / 禅道 / Wiki / 其他
ledger_notes        备注台账（Markdown）：接口信息、坑点、遗留问题、需求变更
note_assets         粘贴进来的截图，文件存 app data 附件目录，库里只存相对路径
milestones          里程碑：阶段（CHECK 五段 立项|评审|联调|上线|验收，与 projects.status 那八段是两套词）、
                    计划日期（TEXT 'YYYY-MM-DD'，可空）、备注、done 勾选 —— **M9 已实现（V5），与 todos 同批**
todos               待办（M9 新增）：所属项目 NOT NULL、内容、截止日期（可空）、done、软删三件套；
                    日期只由写入侧判形状，SQL 不解释日期（`strftime('now')` 是 UTC，会把本机「今天」算错一天）
daily_reports       日报条目（M10 新增，V6）：id / project_id→projects / report_date TEXT NOT NULL / content / hours REAL /
                    created_at / updated_at / deleted_at —— 一天一项目可多条；日期只存形状（`YYYY-MM-DD`，由写入侧 `todo::req_date` 保证），
                    工时上限与两位小数由 Rust 校验（不加 CHECK，否则违例冒成 `db_failed`、把校验失败伪装成库故障）；SQL 不解释日期。

                    skip_reason + error_msg

                    词由 jieba cut_for_search 预切，rowid 与 index_docs.doc_rowid 对齐
vault_meta          KDF salt 与参数、主密钥两份包裹、恢复码哈希
settings            键值：排除规则、大小上限、监听开关等
```

所有业务表统一带 `id`(uuid TEXT PK) / `created_at` / `updated_at` / `deleted_at`（软删除）——这是「预留多人」唯一现在要付的代价，其余不动。

**台账导出是只读功能（M11-b）**：`ledger_export` 不新增表、不改 `TARGET_VERSION`，只读 `ledger_envs` / `ledger_credentials` / `ledger_servers` / `ledger_links` / `ledger_notes` 五表并写用户当场在原生对话框里选定的一个文件；**默认路径不查密文列**（列头保留、值留空），只有显式勾选「包含账号与密码明文」并经 in-app 二次确认才解密。落点守卫复用 `backup::guard_destination`：落进数据目录一律拒（`backup_destination_unsafe`），且守卫在任何写盘之前。

**`index_status` 必须在建表时就设计进去。** 全文检索最难排查的不是「搜错」而是「搜不到」；UI 要能直接回答「这个文件为什么不在结果里」（超限/类型不支持/抽取失败/尚未索引），而不是让用户怀疑功能坏了。后补这个字段要重建索引。

**密文列不参与任何检索。** FTS 索引密文没有意义，规划搜索范围时明确排除。M2 的库内字段检索（`search.rs`）把这条做成结构性保证：九段 SQL（M10 起含日报正文与待办标题两类，M11-a 起含到期事项名称与备注）的 `SELECT`/`WHERE` 里**只写明文列**，`*_cipher`/`*_nonce` 连字符串都不出现，所以「用密码去搜不到」不依赖查询后的过滤——后者只要漏一处就泄漏。M3 建 FTS 索引时同样只喂明文列。

---

**工作区是逻辑分区，不是访问控制**：同库同进程，任何拿到 `ledger.db` 的人都能读到全部工作区的数据。隔离的兑现点是「后端按当前区过滤读写」，不是加密、不是权限（M15 spec §十二.6）。

**索引抓取不按区开关**：后台 worker 照旧扫所有未删项目的根目录（`index_job.rs` 的 `targets()`），按区收窄只发生在呈现与写入这一层。理由是重扫代价与增量机制（mtime）跟 UI 视野无关（M15 spec §4.1 / §十二.8）。

## 五、安全设计

- **主密钥 MK**：安装时生成 32 字节随机数，永不离开内存/不以明文落盘。
- **KDF**：Argon2id 从主密码派生 KEK（记录 salt、m_cost、t_cost、p_cost 到 `vault_meta`）。
- **列级加密**：敏感列用 AES-256-GCM 加密为 `*_cipher` BLOB + `*_nonce` BLOB，明文列不加密、可索引可查询。M2 落地的白名单是四列（`ledger.rs` 的 `SECRET_FIELDS`）：凭据的 `username`/`password`、服务器的 `account`/`password`；新增敏感列必须同时改这张表和建表迁移，否则 IPC 侧直接拒（有测试守着）。项目档案里的手机号/对接人当前是明文，需要加密时按同一套加列。AAD 绑定 `行 id + 列名`，防止密文跨行/跨列挪用。
- **双包裹（这里指恢复路径，不是 DPAPI）**：MK 同时用 ①主密码派生密钥 ②一次性恢复码派生密钥 各包裹一份存 `vault_meta`。
  - 选 ①：换机器只要拿到备份包 + 主密码即可解密。
  - 选 ②：忘记主密码时用设置时展示的恢复码解锁并重新设置主密码。
  - **不承诺「无任何凭据可恢复」**，也不引入 DPAPI：DPAPI 结果绑定机器/用户 profile，重装即不可解，只适合当便利层，而需求里没有免密诉求（导图写的是「开机主密码解锁」）。
- **UI**：敏感字段默认脱敏，点击显示、一键复制；显示明文不写日志。
- 主密码校验用「能否成功解开 MK」判定，不单独存密码哈希。

## 六、索引与备份

### 6.1 索引

- 默认对**所有已登记项目根目录**全量构建，后台分批、可断点续建、可暂停；首轮几分钟可接受。
- 排除规则（可配置）：`node_modules`、`dist`、`build`、`target`、`__pycache__`、`.git`、压缩包、`.tmp/.log`。
- 上限：单文件 20 MB，单项目 5 万文件；超限记 `skipped` + 原因。
- 抽取按扩展名分派，跑在 worker 线程池内并 `catch_unwind` 兜住 panic（依赖 release 保持 unwind：`[profile.release]` 里出现 `panic = "abort"` 会让这两道 `catch_unwind` 在发布构建里全部失效，见 2.2 同一行与 `extract::release_profile_does_not_abort_so_panic_guards_work`），一个坏文件不能打挂整轮索引。边界打在两处：`extract::pdf_text` 内部（PDF 一条）与 `index_job` 的 pass 调用点 `panic_to_err`（四条路径全兜），worker 线程体最外层还有一道，任何 panic 都必定产生一个终态事件。
- 文本读取一律走 `chardetng` 探测 + `encoding_rs` 解码。**不假设 UTF-8**——Windows 中文环境 GBK 必然出现，假设了就得到一片乱码索引，而且不报错，只是永远搜不到。
- 检索走**两段**：先「精确段」（查询词原样进 MATCH），该段 0 命中才放宽到「前缀段」（每个词加 `*`），命中的行带 `matchedBy = exact|prefix` 标注。不靠改用户查询词做拼音/同义词，噪音由标注暴露给前端，M4 可按它分组而不是混排。
- **未支持的类型不建行**（也不占单项目配额）——几十 GB 目录里二进制占大头，全建行会把表撑爆；「这个文件为什么不在结果里」由 `/index` 页面明示的支持清单回答，共 **29 项**（17 个纯文本/代码扩展名 + `docx`/`pptx`/`xlsx`/`xls`/`pdf` + M6 起的 `png`/`jpg`/`jpeg`/`webp`/`bmp` + M7 起的 `doc`/`ppt`）。**图片自 M6 起经 Windows 原生 OCR 纳入索引**（需本机装有可用语言包；无包时图片在扫描门退回「不建行、不占配额」，`/index` 有一行 OCR 启用/未启用提示）；**`.doc`/`.ppt` 旧版 Office 自 M7 起经本机 LibreOffice 无头转换纳入索引**（转成 docx/pptx 后走既有 `office_text` 抽正文，产物用完即删、不入库；探不到 LibreOffice 时这两类在扫描门退回「不建行、不占配额」，`/index` 有一行状态与一个「安装 LibreOffice」按钮）。压缩包仍不索引。
- UTF-16 不用自己判 BOM：走 `Encoding::decode`（不是 `decode_without_bom_handling`），它内部先跑 `for_bom`，UTF-8/UTF-16LE/UTF-16BE 的 BOM 会**盖过 chardetng 的猜测结果**并顺手剥掉 BOM——chardetng 自己根本没有 UTF-16 模型。没有 BOM 的 UTF-16 仍会被猜成单字节编码，属已知残留口子。
- 变更检测（**M5 已交付的是后一半**，2026-10-10）：**启动 `reconcile`** —— 每次启动自动跑一轮增量追平，把「登记还在、磁盘上没了」的路径按项目做差集回收：主行 `index_status='missing'`、同 rowid 的 FTS 行点位删除（元数据行保留，文件放回后下一轮自愈回 `ok`）。`notify` 实时监听**缩量到 M5.5**，理由见 `docs/superpowers/specs/2026-10-10-m5-reconcile-design.md` §九：先让"重启即可见"这条最便宜的路径把痛点收掉，监听器的取消语义、跨卷与网络盘事件风暴还没设计完。回收侧三条硬闸门（root 不可达整项目跳过、被上限截断的那一轮不回收、比例熔断 `candidates*2 > 已跟踪行 && candidates > 20`）是为了让"误标"永远只是少标而不是多标 —— 真机已实测 25 行缺 24 时一格没标、缺 3 时标 3。
- **索引行的生命周期以登记的 root 行为作用域**：注销根目录（`remove_dir` 删到 `kind='root'`）或改指新根（`set_root_dir` 换到不同路径）时，同步回收 `index_docs` 与 `index_docs_fts` 双侧行——根行一没，`index_job::targets()` 就不再列出该项目，`clear_project` 对那些行永久不可达，旧根的文件会继续命中搜索（终审 I3）。同一路径重复登记**不**回收，免得一次无意义的登记重写变成全量重抽。M5 的 reconcile 处理的是另一种形态（登记还在、文件没了），覆盖不到这里。删 `entry` 类快捷入口也不动索引：它从来不是索引作用域。作业运行中做注销/换指这两件事时，`busy_timeout` 只保证**不撞锁**、不保证**回收不被覆写**：那一轮 `run_pass` 仍握着轮次开头那一次 `targets()` 快照，会在删除之后继续为该项目的文件写行，把刚回收的行写回来；所以 `run_pass` 正常完成的末尾还有一次 `index_job::sweep_unrooted_projects`，把「登记里没有 root 行的项目」的双侧行回收掉（整改之前遗留的历史残留同走这一条，用户无需任何操作）。收敛时机是**本轮末尾或下一轮末尾，不是即时**；软删项目（`deleted_at` 非空）的行不在 sweep 范围内——`SELECT_SQL` 已把它们挡在检索外，行留着是给项目恢复用的。

### 6.2 备份包

- 内容：`ledger.db`（走 **SQLite Backup API** 的运行时快照，**不直接拷 .db**——WAL 模式下裸拷可能拿到不一致状态或丢掉未 checkpoint 的数据）+ `vault_meta`（含两份包裹与 KDF 参数）+ `manifest.json`（版本、时间、app 版本、各文件 SHA-256）→ 打成 zip。**M8 已交付（2026-10-14）的实态**：包里**只有两条目** —— `manifest.json` + `backup.db`；`vault_meta` 不是独立条目，它本来就是 `ledger.db` 里的一张表，跟着库一起进包（含两份包裹与 KDF 参数，所以换机导入后主密码/恢复码仍解得开）。zip 侧文件 `-wal`/`-shm` 一条都不许混进来（快照连接必须先关，见下条）；包内条目只按 `manifest.files` 点名的取，**未被点名的条目一律忽略且永不落盘**（这一句就是 zip-slip 的防法）。
- **索引不进备份包**，换机器后在新机器重建。机制（D4）：Backup API 拿到整库一致快照后，在那份快照上 `DELETE FROM index_docs_fts; DELETE FROM index_docs;` 再 `VACUUM`，**关掉快照连接之后**才把字节读进 zip（顺序错了会拷到一个引用不存在 `-wal` 的陈旧影像）。索引不进包不是省体积，是省掉「包里的索引行指向新机器上不存在的路径」这类假命中；导入后**不**自动起索引轮（D7），界面只给一句提示 + 去 `/index` 的链接。
- 导入前校验 manifest 哈希，不匹配就拒绝并说明是哪个文件损坏。M8 的实态是**四道前置、全过才动库**（解包读 manifest → 比 `formatVersion` → 比 `schemaVersion`（只拒「包比本机新」）→ 验 db 的大小与 SHA-256），且**覆写永远可撤销**：动库之前先在**数据目录**里存一份 `pre-restore-<UTC 秒>-<pid>-<seq>-<纳秒>.zip` 应急包（同秒连导两次也不会吃掉前一份撤销键），之后才 `Connection::restore` 灌进**当前已打开的那条连接**（不覆盖在用的 `ledger.db` 文件、不重启）。`restore` 会**绕过 `after_open`** ⇒ 导入后必须现读一次 WAL 并补跑迁移，两条各挂一支错误码（`backup_wal_lost` / `backup_migrate_failed`）。
- **写盘范围的硬门（M8 终审 C1 补的，红线条③ 的代码化）**：`zip_out` 用的是 `File::create`（CREATE_ALWAYS + **截断**），而 Windows 的共享规则**保护不了正被 SQLite 开着的** `ledger.db` —— 本机实测把导出落点指进数据目录会让文件长度当场归零。所以 `backup_export` 在任何写盘之前先过一道 `backup::guard_destination(data_dir, dst)`：**落点解析后落在数据目录里就拒**（不只 `ledger.db`，`pre-restore-*.zip` 是别人的撤销键、同样不许覆），新码 `backup_destination_unsafe`。`import` 自己写应急包那一支刻意不套这道守卫（那本来就该落在数据目录里）。**这条是"只新增文件、绝不删改既有文件"这条红线唯一由代码保证的地方**，不由对话框保证 —— 对话框只保证人当场选了一次路径。
- 附件（截图）单独打包或一并放进 zip —— 定为一并放入。**（2026-10-14 附注：本条本轮没兑现，是刻意缩量 —— 附件表 `note_assets` 从 M1 到现在一直没实现，笔记截图至今仍按原始路径「重新获取」，没有可打包的派生产物 ⇒ 「一并放入」没有对象可放。真实现 `note_assets` 那一轮，附件目录跟着进同一个 zip：`manifest.files` 的条目集合本来就为多条目留了位置，验包逻辑也只按点名的取。）**
- **M9 的两张新表（`todos` / `milestones`）随整库快照进包，但不进 `counts` 摘要（D9，需求方当次批准）**：备份取的是整库一致快照，新表不需要任何接线就跟着走；`backup::Counts` 那七个 camelCase 字段刻意**没**加第八、第九项。理由是诚实而不是省事 —— 旧包（M8/M8.1 导出的那批）的 manifest 里没有这两项，补字段只能靠 `#[serde(default)]` 显示 `0`，而「这个包里有 0 条待办」对一份装着 12 条待办的旧包是句假话（与 M8 终审 I1「库已覆写之后 `vault_status` 继续报 `unlocked: true`」同族的界面撒谎）。⇒ 后果登记在 spec §十二 风险 6：`/backup` 界面看不到待办/里程碑的行数，要验就导一份包、`backup_inspect` 之后直查包内 `backup.db` 的两张表。
- **M10 的新表（`daily_reports`）随整库快照进包、但不进 `counts` 摘要（沿用 M9 D9 那一条裁定，需求方当次批准）**：备份取的是整库一致快照，新表不需要任何接线就跟着走；`backup::Counts` 那七个 camelCase 字段刻意**没**为它加第八项。理由与待办/里程碑那一格一字不差 —— 旧包补默认值只能靠 `#[serde(default)]` 显示 `0`，而「这个包里有 0 条日报」对一份装着日报的旧包是句假话。⇒ 后果同样落在 `/backup`：界面看不到日报的行数，要验就导一份包、`backup_inspect` 之后直查包内 `backup.db` 的 `daily_reports` 表。
- **M11-a 的新表（`project_expiries`）随整库快照进包、同样不进 `counts` 摘要（沿用上面那两条裁定，需求方当次批准）**：`backup::Counts` 那七个字段本轮**没加第八项**，真机沙盒导出+验包读到的 `counts` 键集合仍是七键（`ledgerCredentials,ledgerEnvs,ledgerLinks,ledgerNotes,ledgerServers,projects,settings`），包内 `schemaVersion = 7`。**本轮同步改准的是另一句**：`warn_plaintext_columns()` 那句明文告警已含「**到期事项名称与备注**」—— M10 终审 I1 的同一格（那句当时没有任何一格分配到 `backup.rs`，九次任务级评审结构性看不见它），本轮把它写成不变量并钉进一格，取证是 `backup.rs` 的 `plaintext_warning_names_every_plain_text_table_since_m9`。⇒ 界面看不到到期事项行数的后果与上面两格同形：要验就导一份包、`backup_inspect` 之后直查包内 `backup.db` 的 `project_expiries` 表。

### 环境已修问题

1. cargo 取不到索引不是网络不通，是 **Windows 系统代理指向 `127.0.0.1:7897` 而代理软件未运行**（`ProxyEnable=1`；git 全局 `http.proxy` 同样是 `127.0.0.1:7900`）。直连 `index.crates.io`/`static.crates.io`/`api.github.com` 均 200。
   处理方式：**在项目内落 `.cargo/config.toml` 写 `[http] proxy = ""`**，实测三种绕法都可用，选这个是因为它只影响本仓库、不动用户全局配置。git 操作用 `git -c http.proxy=` 单次覆盖。
2. **Tauri 默认 dev 端口 1420 在本机不可用**：Windows 把 `1397–1496` 整段列为 TCP 排除端口（`netsh interface ipv4 show excludedportrange protocol=tcp`，Hyper-V/WSL 保留），Vite 监听直接 `EACCES: permission denied ::1:1420`。已把 dev 端口改为 **1520**，`vite.config.ts` 的 `server.port` 与 `tauri.conf.json` 的 `devUrl` 必须同步改。hmr 端口同理改 1521。
3. `crates.io` 的 REST API 必须带自定义 User-Agent，否则 403（与 cargo 的失败无关，是两件事）。

### 样式约定（需求方指定）

- **优先使用 Tailwind CSS 工具类**，组件内不散落自定义 class 与内联 style。
- 确实需要工具类表达不了的样式（复杂嵌套选择器、关键帧动画、富文本渲染、滚动条等）时，**新建 `.scss` 文件**承载，不新增裸 `.css` 文件；已装 `sass` 1.105.1。SCSS 内用 `@use` 而非已弃用的 `@import`。
- **唯一例外**：Tailwind 4 + shadcn/ui 的主题 token 入口 `src/styles.css` 保持 `.css`。它含 `@import "tailwindcss"`、`@custom-variant`、`@theme inline`、`@layer base` + `@apply` 这些 Tailwind 4 专属 at-rule，交给 sass 编译会出问题，改它是净损失。

## 九、默认值（需求方可改）

- 忘记主密码：一次性恢复码，不承诺无凭据可恢复。
- 单文件上限 20 MB；单项目文件上限 5 万。
- 排除目录/扩展名清单如上。
- OCR 仅 png/jpg/jpeg/webp/bmp 且 ≤20 MB，后台队列不阻塞搜索。
- 旧格式 `.doc`/`.ppt` 依赖本机装有 LibreOffice（探 `soffice.com` 三个候选位），**无开关、探到即用、装完不必重启**；探不到时整类不建行不占配额。单份转换实测 ≈2.12 s（30 份真测首轮 63.7 s），只在该文件首次进入索引那一轮付。
- 索引表与台账表同库不同表（不拆两个文件，保证备份口径一致）。M8 兑的就是这句的另一半：正因为索引行和台账行在**同一个文件**里，备份没法按文件剥掉索引，只能**按表剥** —— `backup::strip_index` 那两条 `DELETE` + `VACUUM` 就是「索引不进包」的全部实现，判据在 `index_job.rs` 的端到端往返里（包里 `index_docs`/`index_docs_fts` 读出来是 0，而活库那一轮真扫出了行）。
- `notify` 监听默认开，设置页可关。**（2026-10-10 附注：本条没兑现 —— `notify` 随 M5 缩量推到 M5.5，`grep notify src-tauri/Cargo.toml` 仍 exit=1 是本轮硬门之一。现状是「每次启动无条件跑一轮增量追平」，没有开关、也没有设置页；要关掉只能改 `lib.rs` setup 那一行。真机实测这一轮会让首个写命令排队到 `busy_timeout` 的 5 s（超线时直接 `db_failed`），所以 M5.5 加开关之前先要定「让路策略」，见 `docs/开发进度.md` 的 M5 finding 1。）**
- TanStack Router 用 hash history。

## 十、已知风险与未验证项

1. 本方案的性能、索引体积数字均为估算，**未做运行时验证**。M3 需先跑小样本实测（拿 2-3 个真实项目目录建索引）再决定批次大小。
2. token 空间 `snippet()` 的去空格清洗对「标点被切成独立 token」的情况不完美的，需在 M3 验证，必要时降级为「显示文件前 N 字 + 子串高亮」。
3. `jieba-rs` 默认词典对业务专有名词（项目代号、客户简称）切分可能不准，需验证是否要加自定义词典。
4. Windows OCR 需要系统语言包支持中文，缺失时的降级路径待 M6 验证。**（M6 已落地：本机 2026-10-12 探得 `AvailableRecognizerLanguages().Size()>0`、OCR 出中文；无包路径由 `ocr_available()` 探测 + `index_scan` 的降级门实现为「图片不建行、不占配额」+ `/index` 一行「图片 OCR 未启用」提示。整台机器无包的端到端体验本机造不出（装了 `zh-Hans-CN`），降级只在扫描层纯函数测证。）**
5. PDF 扫描件抽出为空属于正常而非失败，需与 `skipped`/`ok` 语义区分清楚，否则用户会以为索引坏了。
6. **备份包本体不加密，这是 M8 交付时就摊开的设计代价，不是漏洞**（2026-10-14）。库里只封四列 `*_cipher`（账号/口令/服务器账户与密码），其余列 —— 项目名/编号/负责人/客户/联系人/合同号、服务器 `ip` 与堡垒机、各类 `url`、各表 `note` —— **全是明文**，一个未加密的包 ≈ 一份内网入口清单。两处点名：包内的 `manifest.plaintextWarning`，以及 `/backup` 页头那句**无条件渲染**的静态文案（T8 评审抓的就是「只在验包成功之后才出现」这一条，真机 DOM 复验过）。包口令/密封装是另一轮的事（spec D6 明确不在本轮），眼下唯一防线是「别把包发到共享盘/群里」。
7. **索引轮与导入之间那道闸是「大幅收窄」而不是互斥**（2026-10-14，spec D13）。`backup_import` 先问 `not_indexing()`，但 `index_job::start` 从不取 `state.conn`（worker 自开连接），所以闸门挪进锁内也关不掉那个窗口；真闭合要一面 `restore 进行中` 的原子旗由 `index_job::start` 一起看，那要动 `index_job.rs`，M8 裁定不做。后果被两件事兜住：那一轮写回来的只是**索引行**（台账/密文列不受影响，且下一轮 `reconcile`/重扫会自愈），以及导入自己那份**覆写前应急包**始终在数据目录里。真机取到的读数是「索引轮在跑时点导入 ⇒ `backup_busy`，库一字未动」。
