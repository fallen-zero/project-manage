## 一、需求确认结论

| # | 结论 | 对架构的影响 |
|---|---|---|
| 1 | 痛点是「上次那个文件/网址/账号在哪」 | 软件是**检索优先**，不是台账优先 |
| 2 | 首屏 = 一个搜索框 | 搜索是默认路由与主导航入口 |

## 二、技术选型与依据

### 2.1 检索引擎：SQLite FTS5 自研索引（方案一，已采纳）

被否掉的两条：

- **tantivy + SQLite 双存储**：几十 GB 量级付不起「文件改名/删除要两边同步、备份要打包两处」的一致性代价。搜索质量上限最高，但不是当前瓶颈。
- **嵌 `dowse` 当引擎**：它是纯文件维度引擎，没有台账概念，「搜一个词同时命中项目/网址/PDF 正文并按项目分组」要在应用层拼两次查询再归并，首屏体验割裂；且 crates.io 只到 0.10.0（2026-07-21），GitHub 已 1.1.0 且 OCR 在其后，走 crates.io 拿不到 OCR，走 git 依赖等于钉在单人维护、版本流动的仓库上。
- **复用 Windows Search API：不建议。** 强依赖目标机开启索引服务且范围正确，公司电脑常被 IT 策略关闭；结果无法按项目/标签过滤；换机器行为不一致。

**选 FTS5 的真正理由不是性能，是一处真值来源**：台账、正文索引、索引状态全在同一个 SQLite 文件里，备份、迁移、一致性、按项目/标签过滤全部退化成一个 SQL。

### 2.2 已核实的库内部行为（不是凭印象）

| 论断 | 证据 |
|---|---|
| `rusqlite` 的 `bundled` 一定带 FTS5 | `libsqlite3-sys/build.rs:163` 在 bundled 编译路径上无条件 `.flag("-DSQLITE_ENABLE_FTS5")`，无 feature 开关 |
| `pdf-extract` / zip+XML 解析对畸形输入会 **panic 而非返回 Err** | 借鉴对象 `dowse::extract` 把所有抽取包在 `catch_unwind` 里，注释明确指出这一点 → 抽取必须跑在独立 worker 线程 |
| Windows 原生 OCR 会在中文字符间插入空格，不清洗就永远搜不到 | `dowse::ocr::clean_cjk_spaces()` 专为删这个问题而写（仅当空格两侧都是 CJK 才删，保留英文词间空格） |
| 旧格式 .doc 纯 Rust 无可靠方案 | `dowse` 与 `calamine` 都只覆盖 docx/xlsx/pptx/xls，Word 二进制 .doc 不在列 → 需外部 `soffice --headless` |
| `opener` 的 `allow-open-path` 权限**只放行命令，不含任何路径 scope** | `tauri-plugin-opener-2.7.0/permissions/autogenerated/commands/open_path.toml` 注明 "without any pre-configured scope"；`src/scope.rs:127-140` 把 capability 里该权限的 `allow` 条目喂给 `tauri::fs::Scope`，条目为空即 `is_path_allowed=false` → 只在 permissions 里写字符串会得到 "Not allowed to open path"（M1 真机复现）。本项目必须写成 `{ "identifier": "opener:allow-open-path", "allow": [{ "path": "**" }] }` |
| `navigator.clipboard.writeText` 在 webview 失焦时抛 `Document is not focused` | M1 真机复现（CDP 驱动时窗口未聚焦）。"一键复制路径/密码"是核心动作，静默失败不可接受 → 改用 `tauri-plugin-clipboard-manager` 的原生剪贴板 |

### 2.3 借鉴来源

`ltspace/dowse`（MIT OR Apache-2.0，最近推送 2026-09-28）。**只读源码作参照实现，不作为依赖。** 要借鉴的具体设计：扩展名分派抽取、`chardetng`+`encoding_rs` 编码探测、大小上限与跳过原因、畸形输入的 `catch_unwind`、Windows OCR 队列/worker 池、`reconcile` 启动对账、快慢车道降级思路。

## 三、架构

```
React (WebView)  ── TanStack Router(hash) + zustand + shadcn/ui
      │  只做展示与交互，不碰文件系统
      ▼  invoke() / Tauri IPC（唯一数据通道）
Rust 侧  src-tauri
  ├─ commands   参数校验、返回 DTO
  ├─ service    业务逻辑、事务边界
  ├─ search     jieba 分词 → FTS5 查询 → 结果分组
  ├─ index      walkdir 扫描 → 抽取 → 写库（rayon 线程池 + catch_unwind）
  ├─ extract    按扩展名分派：pdf / docx / xlsx / pptx / text
  ├─ crypto     Argon2id KDF + AES-256-GCM 列级加解密
  ├─ vault      主密钥双包裹、恢复码
  └─ backup     SQLite Backup API 快照 → zip 备份包 + SHA-256
                     ▼
              本地单文件 SQLite（WAL）+ 附件目录
```

**硬性约束：文本抽取、分词、写库、加密全部在 Rust 侧。** 放 webview 会同时丢掉编码控制、流式读取和性能。

### 3.1 数据库打开（不可省校验）

`PRAGMA journal_mode=WAL` 之后**必须读回 `PRAGMA journal_mode` 断言等于 `wal`**，不能相信 `pragma_update` 返回的 Ok——数据目录可能落在网络盘/被杀软拦截的路径，设置会静默失败。校验不过就明确报错并提示换本地磁盘，不静默降级。

### 3.2 中文分词

FTS5 原生 tokenizer 在中文上一定失效且症状隐蔽（`unicode61` 把整句连续中文切成一个巨型 token；`trigram` 要求查询 ≥3 字符，而中文高频是 2 字词）。

做法：**入库前用 `jieba-rs` 切词，以空格连接写入 FTS 列，FTS5 表本身配 `unicode61` 即可**（切词工作已前移）。

**硬约束：入库与查询必须用同一个分词器、同一套预处理**（同版本词典、同停用词、同 lower / 全半角处理）。为此把预处理收敛成一个函数 `tokenize_for_index(s) -> String`，入库和查询两侧共用，禁止任何一侧私自加处理。FTS 虚表用 `rowid` 对齐主表主键，不把业务 id 塞进虚表列。

### 3.3 摘要与高亮策略

不在 token 空间做偏移映射（分词后位置对不回原文）。改为：

- **结果列表摘要**：FTS5 `snippet()` 在 token 文本上生成，展示前做去人为空格清洗。
- **点开命中**：按需从磁盘原文件重新抽取，在**原文**上做子串大小写不敏感高亮。既省存储又准确，且符合「只读、不动源文件」的边界。

### 3.4 跨域结果合并

台账（SQL 匹配）与正文（FTS BM25）的分数不可直接比较。**不做假的归一化**：结果按「项目 / 台账条目 / 文件正文」分组展示，组内各自按 BM25 或时间排序，命中的台账与文件在所属项目下聚合。

## 四、数据模型

```
projects            项目：名称/编号/经理/客户/对接人/合同编号/合同周期/交付截止/status/标签
                    status 为全局统一枚举：立项|需求|开发|测试|预发|上线|运维|归档
project_tags        自定义标签（政务/自研/外包/已验收/暂停/维保中/…）
project_dirs        目录映射：kind = root(一个) | entry(多个快捷入口)，仅存路径
ledger_envs         多环境：env = dev|test|pre|prod，名称/URL/端口/备注
ledger_credentials  账号凭据：绑定 env 或独立，username_*_cipher / password_*_cipher（各配 *_nonce）
ledger_servers      服务器 IP / 堡垒机 / 远程账号：account_*_cipher / password_*_cipher（各配 *_nonce）
ledger_links        外部链接：Jira / 禅道 / Wiki / 其他
ledger_notes        备注台账（Markdown）：接口信息、坑点、遗留问题、需求变更
note_assets         粘贴进来的截图，文件存 app data 附件目录，库里只存相对路径
milestones          里程碑：阶段、日期、备注
project_versions    版本台账：版本号、上线时间、上线内容
index_docs          每个文件一行：doc_rowid(自增，给 FTS 当 rowid) / id(uuid) / path / ext /
                    size / mtime / index_status = pending|ok|skipped|failed|missing +
                    skip_reason + error_msg
index_docs_fts      FTS5 虚表：name_tokens + body_tokens，tokenize=unicode61；
                    词由 jieba cut_for_search 预切，rowid 与 index_docs.doc_rowid 对齐
vault_meta          KDF salt 与参数、主密钥两份包裹、恢复码哈希
settings            键值：排除规则、大小上限、监听开关等
```

所有业务表统一带 `id`(uuid TEXT PK) / `created_at` / `updated_at` / `deleted_at`（软删除）——这是「预留多人」唯一现在要付的代价，其余不动。

**`index_status` 必须在建表时就设计进去。** 全文检索最难排查的不是「搜错」而是「搜不到」；UI 要能直接回答「这个文件为什么不在结果里」（超限/类型不支持/抽取失败/尚未索引），而不是让用户怀疑功能坏了。后补这个字段要重建索引。

**密文列不参与任何检索。** FTS 索引密文没有意义，规划搜索范围时明确排除。M2 的库内字段检索（`search.rs`）把这条做成结构性保证：六段 SQL 的 `SELECT`/`WHERE` 里**只写明文列**，`*_cipher`/`*_nonce` 连字符串都不出现，所以「用密码去搜不到」不依赖查询后的过滤——后者只要漏一处就泄漏。M3 建 FTS 索引时同样只喂明文列。

## 五、安全设计

- **主密钥 MK**：安装时生成 32 字节随机数，永不离开内存/不以明文落盘。
- **KDF**：Argon2id 从主密码派生 KEK（记录 salt、m_cost、t_cost、p_cost 到 `vault_meta`）。
- **列级加密**：敏感列用 AES-256-GCM 加密为 `*_cipher` BLOB + `*_nonce` BLOB，明文列不加密、可索引可查询。M2 落地的白名单是四列（`ledger.rs` 的 `SECRET_FIELDS`）：凭据的 `username`/`password`、服务器的 `account`/`password`；新增敏感列必须同时改这张表和建表迁移，否则 IPC 侧直接拒（有测试守着）。项目档案里的手机号/对接人当前是明文，需要加密时按同一套加列。AAD 绑定 `行 id + 列名`，防止密文跨行/跨列挪用。
- **双包裹（这里指恢复路径，不是 DPAPI）**：MK 同时用 ①主密码派生密钥 ②一次性恢复码派生密钥 各包裹一份存 `vault_meta`。
  - 选 ①：换机器只要拿到备份包 + 主密码即可解密。
  - 选 ②：忘记主密码时用设置时展示的恢复码解锁并重新设置主密码。
  - **不承诺「无任何凭据可恢复」**，也不引入 DPAPI：DPAPI 结果绑定机器/用户 profile，重装即不可解，只适合当便利层，而需求里没有免密诉求（导图写的是「开机主密码解锁」）。
- **UI**：敏感字段默认脱敏，点击显示、一键复制；显示明文不写日志。
- 主密码校验用「能否成功解开 MK」判定，不单独存密码哈希。

## 六、索引与备份

### 6.1 索引

- 默认对**所有已登记项目根目录**全量构建，后台分批、可断点续建、可暂停；首轮几分钟可接受。
- 排除规则（可配置）：`node_modules`、`dist`、`build`、`target`、`__pycache__`、`.git`、压缩包、`.tmp/.log`。
- 上限：单文件 20 MB，单项目 5 万文件；超限记 `skipped` + 原因。
- 抽取按扩展名分派，跑在 worker 线程池内并 `catch_unwind` 兜住 panic，一个坏文件不能打挂整轮索引。
- 文本读取一律走 `chardetng` 探测 + `encoding_rs` 解码。**不假设 UTF-8**——Windows 中文环境 GBK 必然出现，假设了就得到一片乱码索引，而且不报错，只是永远搜不到。
- 检索走**两段**：先「精确段」（查询词原样进 MATCH），该段 0 命中才放宽到「前缀段」（每个词加 `*`），命中的行带 `matchedBy = exact|prefix` 标注。不靠改用户查询词做拼音/同义词，噪音由标注暴露给前端，M4 可按它分组而不是混排。
- **未支持的类型不建行**（也不占单项目配额）——几十 GB 目录里图片/二进制占大头，全建行会把表撑爆；「这个文件为什么不在结果里」由 `/index` 页面明示的支持清单回答，共 22 项（17 个纯文本/代码扩展名 + `docx`/`pptx`/`xlsx`/`xls`/`pdf`）。图片、压缩包与 `.doc`/`.ppt` 旧版 Office 本版本明确不索引（OCR 归 M6、旧格式归 M7）。
- UTF-16 不用自己判 BOM：走 `Encoding::decode`（不是 `decode_without_bom_handling`），它内部先跑 `for_bom`，UTF-8/UTF-16LE/UTF-16BE 的 BOM 会**盖过 chardetng 的猜测结果**并顺手剥掉 BOM——chardetng 自己根本没有 UTF-16 模型。没有 BOM 的 UTF-16 仍会被猜成单字节编码，属已知残留口子。
- 变更检测：M5 引入 `notify` 监听 + 启动 `reconcile`（追平软件未运行期间的变化，含文件删除/改名后路径失效标记）。

### 6.2 备份包

- 内容：`ledger.db`（走 **SQLite Backup API** 的运行时快照，**不直接拷 .db**——WAL 模式下裸拷可能拿到不一致状态或丢掉未 checkpoint 的数据）+ `vault_meta`（含两份包裹与 KDF 参数）+ `manifest.json`（版本、时间、app 版本、各文件 SHA-256）→ 打成 zip。
- **索引不进备份包**，换机器后在新机器重建。
- 导入前校验 manifest 哈希，不匹配就拒绝并说明是哪个文件损坏。
- 附件（截图）单独打包或一并放进 zip —— 定为一并放入。

### 环境已修问题

1. cargo 取不到索引不是网络不通，是 **Windows 系统代理指向 `127.0.0.1:7897` 而代理软件未运行**（`ProxyEnable=1`；git 全局 `http.proxy` 同样是 `127.0.0.1:7900`）。直连 `index.crates.io`/`static.crates.io`/`api.github.com` 均 200。
   处理方式：**在项目内落 `.cargo/config.toml` 写 `[http] proxy = ""`**，实测三种绕法都可用，选这个是因为它只影响本仓库、不动用户全局配置。git 操作用 `git -c http.proxy=` 单次覆盖。
2. **Tauri 默认 dev 端口 1420 在本机不可用**：Windows 把 `1397–1496` 整段列为 TCP 排除端口（`netsh interface ipv4 show excludedportrange protocol=tcp`，Hyper-V/WSL 保留），Vite 监听直接 `EACCES: permission denied ::1:1420`。已把 dev 端口改为 **1520**，`vite.config.ts` 的 `server.port` 与 `tauri.conf.json` 的 `devUrl` 必须同步改。hmr 端口同理改 1521。
3. `crates.io` 的 REST API 必须带自定义 User-Agent，否则 403（与 cargo 的失败无关，是两件事）。

### 样式约定（需求方指定）

- **优先使用 Tailwind CSS 工具类**，组件内不散落自定义 class 与内联 style。
- 确实需要工具类表达不了的样式（复杂嵌套选择器、关键帧动画、富文本渲染、滚动条等）时，**新建 `.scss` 文件**承载，不新增裸 `.css` 文件；已装 `sass` 1.105.1。SCSS 内用 `@use` 而非已弃用的 `@import`。
- **唯一例外**：Tailwind 4 + shadcn/ui 的主题 token 入口 `src/styles.css` 保持 `.css`。它含 `@import "tailwindcss"`、`@custom-variant`、`@theme inline`、`@layer base` + `@apply` 这些 Tailwind 4 专属 at-rule，交给 sass 编译会出问题，改它是净损失。

## 九、默认值（需求方可改）

- 忘记主密码：一次性恢复码，不承诺无凭据可恢复。
- 单文件上限 20 MB；单项目文件上限 5 万。
- 排除目录/扩展名清单如上。
- OCR 仅 png/jpg/jpeg/webp/bmp 且 ≤20 MB，后台队列不阻塞搜索。
- 索引表与台账表同库不同表（不拆两个文件，保证备份口径一致）。
- `notify` 监听默认开，设置页可关。
- TanStack Router 用 hash history。

## 十、已知风险与未验证项

1. 本方案的性能、索引体积数字均为估算，**未做运行时验证**。M3 需先跑小样本实测（拿 2-3 个真实项目目录建索引）再决定批次大小。
2. token 空间 `snippet()` 的去空格清洗对「标点被切成独立 token」的情况不完美的，需在 M3 验证，必要时降级为「显示文件前 N 字 + 子串高亮」。
3. `jieba-rs` 默认词典对业务专有名词（项目代号、客户简称）切分可能不准，需验证是否要加自定义词典。
4. Windows OCR 需要系统语言包支持中文，缺失时的降级路径待 M6 验证。
5. PDF 扫描件抽出为空属于正常而非失败，需与 `skipped`/`ok` 语义区分清楚，否则用户会以为索引坏了。
